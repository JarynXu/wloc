# 一次安装，一次定位验证

这是待真机验证的候选，地图实际到达目标才算本次使用成功。不要同时开启旧定位模块和本模块。

1. 在 Shadowrocket 导入本目录的固定链接 `wloc-complete.module`。确认模块名是 **WLOC Local Workspace v2.5 - Typed Location**；停用其它 WLOC/定位诊断模块，再启用这一份。保留旧模块，不删除配置或坐标。
2. 打开或重新载入 `https://wloc-settings.invalid/wloc-control/v2/`。页面显示 **本机控制 · v2.4 保存修正** 是正常的：v2.5 沿用了这版控制页。点一次“读取”；已有目标正确就不用再次保存，目标为空或不正确才设置并保存一次，再核对读取结果。若保存或读取报错，停在这里，不连续重复写入。
3. 打开 Apple 地图，点当前位置按钮，正常等候约一分钟。只需观察蓝点显示目标位置、实际位置，还是无法定位；无需提供坐标、截图或整份日志。不反复开关定位、不重启或重装证书。

一分钟不是保证会产生新 WLOC 请求的时限；系统可能使用缓存。显示实际位置或无定位都不应被说成“已生效”，也不能单凭这一结果断言是哪一层失败。下一步应由证据决定，而非重复上述操作。

## 出错时

如果地图不能定位、显示不对，或出现新的证书警告，停用本候选，旧定位模块也暂时保持停用。不要清理坐标、恢复备份或改变证书信任；必要时恢复测试前的完整配置，并确认地图实际定位恢复。

若其它有效配置仍含 Apple MITM 规则，停用一个模块不一定会去掉全部拦截。出现证书警告不要继续绕过。该候选没有改变 TLS 信任机制。

## 安装校验

- 以 Shadowrocket 的 **v2.5 模块名和固定导入链接**识别新定位层，不能只看网页版本。
- 页面版本刻意保留 v2.4。v2.5 是组合版本，没有声称控制页重新升级。
- 两个 script-path 都指向不可变的 Git commit，不使用 main、测试分支浮动地址或其它“最新版”文件。
- MITM 列表仍只有 `wloc-settings.invalid`、`gs-loc.apple.com`、`gs-loc-cn.apple.com`，没有高德或新增通配符。
