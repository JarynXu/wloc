# 一次安装，直接使用控制页

请使用收到的固定 GitHub 提交链接安装新版。当前保存状态可能尚未确认；不要把升级当成自动恢复或再次保存。

1. 在手机上保留原配置和旧 WLOC 模块，不上传完整配置、证书或日志。停用旧“Apple WLOC 定位修改”模块、之前的 WLOC 诊断模块、v2/v2.1/v2.2/v2.3 工作台，以及旧的“WLOC Local Control Complete - Candidate”整合版，不删除它们；也不要再运行未迁移的旧保存捷径。新模块会对已知旧入口返回固定退役错误以减少误触风险，但不能保证宿主在脚本执行前没有联网。
2. 从 Shadowrocket 的“配置 → 模块 → ＋”新增完整套件链接，不编辑旧模块的 URL。只启用新的“WLOC Local Workspace v2.4 - Bodyless Write”。若出现覆盖旧模块的提示，取消。确认两个脚本下载成功；继续使用已经成功调用本地入口的现有解密设置，不安装额外证书、不关闭 TLS 校验。页面是否可用仍以手机实际行为为准。
3. 关闭旧标签，在新标签打开 https://wloc-settings.invalid/wloc-control/v2/ 。确认页面显示“本机控制 · v2.4 保存修正”。打开页本身不会自动读取位置。若此前保存未确认，先点一次“读取已存位置”，最长等待 20 秒；成功时核对结果，失败时查看固定诊断码，不连续重存。没有必要重新进行一组健康或存储实验。

核对并保存

如果读取的四项设置已经符合目标，不必再次保存。需要修改时填好草稿，点一次保存。新版先用原值备份保护实际改写；目标完全相同会直接确认，不新增备份。若保存回复异常，页面会只读核对一次，期间请等待。显示“读回一致”只说明当时存储与草稿一致；显示未知时不要刷新后连续保存，先读取核对。新请求仍是 POST，坐标在自定义头中，可能被代理网络诊断记录；不要分享完整请求。

使用地图链接

在“从地图链接填入”粘贴分享文字或一个完整链接，点“解析链接”。核对来源坐标系及预览，勾选确认，再点“填入经纬度草稿”。这不会发送请求或保存坐标；精度和随机半径不变。Apple/Google 的坐标系无法由链接可靠确认时需自行选择，不确定就直接复制已知的 WGS84 坐标。短链接无法离线展开，会给出明确提示。详见 MAP-LINKS.md。

默认模块的“WLOC Read Only Snapshot”、“WLOC Bodyless Write”和“WLOC Local Control v2”都启用了 allowMissingOrigin=true，支持可能不带 Origin 的浏览器 GET 与原生快捷指令。这不是身份认证；设备上的其它原生请求也可能调用接口。请保持本版参数，勿通过扩大域名、放宽 TLS 或修改路由来尝试修复。

已有目标与恢复

- 新套件复用 wloc_settings，因此正式存储里已保存的目标仍可读取。旧模块写在 argument 中的目标不会自动迁移。
- 首次实际保存/清除改写前会建立原值备份，并回读确认。该初始备份不自动更新，即使之后操作失败也保留。
- 超时或错误时不要连续点保存。先读当前值核对。需要回到初始状态时使用恢复按钮；它不是撤销任意其它客户端的最近写入。
- 想回到旧模块：先在新页面恢复并确认，再停用新模块、重新启用旧模块。旧版的原有行为和局限（包括其日志设置）也会恢复。不要同时启用两套模块。
- 仅停用新模块不会清除或恢复当前目标；备份也仍留在手机本地存储中。

原捷径

现有地图分享捷径没有被自动改动。可以先直接使用页面；确需保留原地图分享流程时，按照 SHORTCUT-MIGRATION.md 迁移最后的 HTTP 请求，保持原解析及坐标转换。没有提供未经验证的 .shortcut 文件或新的 iCloud 共享链接。

遇到阻碍

保留固定错误码或裁剪后的错误画面即可，不发送真实坐标、节点、证书或完整配置。若仍是证书/连接错误，不降级到 HTTP、不删除 REJECT、不切回带坐标 URL 的 Apple GET 保存入口。新域已完成过一次 GET 连接，不代表所有宿主和系统定位请求都能通过。

新版功能

- 草稿与已存快照分离；读取不会自动覆盖草稿，画布选点和暂存也不会写入正式位置。
- 日志仅含时间、操作、固定诊断码和耗时，不含坐标；反馈时只发送诊断码即可。
- 在线地图经告知后打开外部原版选点页，坐标需复制回本页。不要在旧页保存。“本页暂存”刷新即清空，不是持久收藏。
- 全局/配置模式的路由问题暂不调整，请保持原先能打开页面的运行方式。不要为此删除 REJECT、扩大域名或关闭 TLS 校验。
