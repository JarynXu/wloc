# WLOC 保存、读取、清除与恢复套件

这是整合后的测试版：位置工作台、操作日志、恢复与帮助，以及配对的本机控制脚本和 WLOC 响应脚本。它仍是候选，不代表保存故障或系统定位已经修复。

本次 v2.2 将浏览器读取改为独立无正文 GET 路径，尝试避开 POST 正文处理阶段，见 [READ-ONLY.md](docs/READ-ONLY.md)。保存、清除、恢复和旧 POST 读取接口保持原行为。v2.1 的严格响应诊断继续保留，不接受不匹配的响应，也不自动回退或重试。请求仍最长等待 20 秒；超时并不证明之前的写入没有发生。

全局与配置模式的路由差异暂不处理。当前模块的精确 REJECT、MITM 与代理策略没有为了打开页面而改为放行；请保持原先可以打开页面的运行方式，不据此判断配置模式已修好。

## 安装后如何使用

完整步骤见 [INSTALL.md](docs/INSTALL.md)，原捷径接入见 [SHORTCUT-MIGRATION.md](docs/SHORTCUT-MIGRATION.md)。安装完成后直接打开：

`https://wloc-settings.invalid/wloc-control/v2/`

页面由本机脚本返回，不是外部网站。打开页面不读取或改变已有坐标，不自动载入地图、统计、字体或其它外部资源。

如果上一次保存没有得到确认，安装后先点一次“读取已存位置”，不要先重存、清除或恢复。读取成功会显示已存结果，但不会覆盖当前草稿；需要时再点击“填入草稿”。读取失败只记录固定诊断码，不能把失败当成存储为空。反馈时只提供诊断码，不要发送坐标或完整响应。

### 页面功能的边界

- 位置工作台将草稿与已存快照分开。输入、粘贴坐标、坐标画布和暂存草稿都不会自动保存。
- 地图选点是经告知后打开原版在线页面，再把 WGS84 坐标复制回本页。它不是本页内嵌地图；外部服务会收到网络信息、浏览区域或主动输入的搜索内容。打开时不会附带本页草稿。不要在旧页面点击“储存到设备”。
- 坐标画布没有街道或卫星底图，只是输入辅助。
- “本页暂存”仅在当前页面内存中保存，刷新后清空，不是持久收藏。
- 操作日志最多保留 200 项，只有时间、操作、固定诊断码和耗时，不含坐标、链接、请求正文或任意异常消息。日志不自动上传；导出和清空需主动点击，刷新后也会清空。
- 恢复仍使用首次修改前的备份，不是撤销上一次保存。

## 本次替换范围

旧 WLOC 模块保留在列表中，但启用新整合模块前必须停用旧模块及此前诊断模块。不能把旧模块 URL 改成新 URL，也不能两套响应规则同时启用。

新模块使用两个配对脚本，提供四条互不重叠的拦截规则：

- 旧 Apple 保存路径的退役保护，仅返回固定 410 错误，不读正文或存储、不回显 URL、不执行旧 GET 写入。它降低误触旧捷径的风险，但不保证宿主在脚本运行前没有握手或上游尝试。
- 浏览器读取使用独立的 `/wloc-read/v1/` GET 入口，精确匹配且 requires-body=0，无请求正文，不写入正式位置或备份，也不返回备份原值。它仅返回与旧 query 一致的结果和备份是否存在。
- 同源控制入口 `/wloc-control/v2/` 保留原 POST JSON 保存、读取、清除、恢复，不将坐标放在 URL。
- 配对 `dist/wloc.js` 响应脚本，保留原逻辑，仅修正读取已存数值 0 时的两处判断。模块显式使用 `LogLevel=off&logLevel=off`，在读取位置前关闭脚本日志；只有小写 logLevel 时，原脚本仍可能先记录已存坐标。

旧 Apple-host 路径不再提供 GET 保存功能，仅返回退役错误。旧快捷指令必须迁移末尾请求后再用；原 iCloud 链接不会自动更新。旧模块中的手写 argument 坐标、精度、随机半径不会自动迁移，新模块只复用正式存储 `wloc_settings`。如果原来完全依赖 argument 且正式存储为空，新模块会透传，需要在新页面保存所需值。

原源代码基线为 JarynXu/wloc commit `007ef07550ea0e4706a14739d033a6a8e814e171`。本候选不修改其 main 或已有公开文件。

## 备份与失败行为

首次保存或清除一个已有目标前，控制脚本把原始正式存储保存到 `wloc_settings_control_backup_v2`，回读确认后才尝试写入正式键。当前值或备份无法识别、备份写入未确认、比较发现并发变化时，不改写正式位置。

这份备份创建后不会自动覆盖。即使随后正式写入失败，备份仍保留；其它客户端后来写入的内容不会更新它。“恢复首次修改前状态”指恢复这份初始快照，不是恢复上一次保存的位置。恢复可能覆盖其它客户端后来写入的值，操作前会提示确认。

保存、清除、恢复的成功均需要正式键回读一致。发送后断线、存储写入返回异常或回读失败，都可能发生“数据已写但未收到确认”；页面不会自动重试或回滚，应读取当前结果核对，再决定是否显式恢复。不能承诺任意断电或宿主错误下绝不改变原值。

清除把正式键写为 JSON null；它是逻辑清空，不是物理删除键。备份仍保留在设备存储中，不会自动上传或被页面展示。停用/移除模块不恢复坐标，也不删除备份。要恢复修改前的保存状态，应先在新页面执行恢复并取得确认，再切换回旧模块。

没有已验证的跨脚本原子 compare-and-set。前端会禁止自己同时发多项操作，后端会在正式写入前重新比较原值，但不能消除所有并发竞争。不要在另一页面、旧捷径或自动化中同时修改同一设置。

## 隐私与来源限制

API 保持同源浏览器来源限制，拒绝其它 Origin、跨站 Fetch-Site、GET 变更和普通表单。原 POST 接口仍要求 JSON；独立 GET 读取不需要也不解析请求正文。不提供跨源 CORS 放行。页面 CSP 禁止外部脚本和资源、iframe 嵌入、外部连接及表单提交；不把坐标放进 URL、浏览器持久化存储、cookie 或日志。

为了兼容可能不带 Origin 的浏览器 GET 和原生快捷指令，两个控制入口均显式设置 `allowMissingOrigin=true`。这不是身份认证：设备上的其它原生请求也可能调用接口，原生客户端还能伪造 Origin。请只在信任的设备和配置中启用。简单关闭该参数可能使浏览器读取也被拒绝；本版不提供可靠的客户端身份认证。本套件没有生成令牌、认证凭据或新的系统权限。

“不自动读取/发送真实坐标”不等于零外发保证。用户点保存时，坐标在 POST 请求体中；脚本只在宿主把 HTTP 请求交给它之后才能处理。若代理绕过脚本、先连上游或全局模式改变规则行为，REJECT 的存在不能保证请求体未被其它组件看到。`.invalid` 是保留域，不是 localhost 监听器。不要关闭 TLS 校验或删除 REJECT 来强行成功。

GitHub 安装会发出模块和脚本下载请求及通常的网络元数据。页面读取位置后会把结果显示在手机上；不要分享带真实坐标的截图或完整日志。

## 验证与局限

在完整离线测试包中运行：

```sh
npm install --ignore-scripts
npm run build
npm test
```

构建不需要外部依赖；完整 DOM 回归使用固定版本 jsdom。公开安装目录仅含脚本、模块和说明。测试覆盖页面无初始请求、互斥与超时、POST 协议和跨站拒绝、首次备份、各个读写故障点、异常脱敏、显式 null 数值拒绝、零值/边界、真实配对响应脚本、早期日志关闭、清除透传以及恢复原始值。原仓库的 Stash 输出断言也针对新响应脚本执行；原有 22 项解析测试另行回归，解析器未改动。

测试中的存储与 DOM 为隔离模拟，另有真实 HTTP/fetch 的合成数据验证；protobuf 输入全部合成。浏览器视觉检查和 iOS Safari/Shadowrocket 真机行为仍未完成，DOM 测试不能替代它们。没有真实位置、BSSID、基站数据或 Apple 上游请求。尚无真机证明的部分包括 Safari CSP/同源行为、Shortcuts POST 和重定向、Shadowrocket 请求体/存储/规则顺序，以及 locationd 的 TLS 和实际位置采用。

本套件仍对 Apple 的 WLOC 响应进行改写，没有把原始 WLOC 请求本地化，也不阻止它按现有代理设置发送给 Apple。隔离的是保存控制入口。

保存成功只确认本地存储，不等于系统定位已生效。若 locationd 仍在 TLS 握手阶段退出，响应脚本仍无机会执行；本套件不能宣称解决该层限制。
